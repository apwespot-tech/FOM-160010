# «Ищу компанию» — совместные активности

Сервис для поиска участников на небольшие события: настольные игры, прогулки, спорт, кино.
Организатор создаёт активность с датой, местом и лимитом участников, остальные находят её в каталоге и записываются.

Подробнее: [описание проекта](docs/project.md).

## Стек

Vue 3 + TypeScript + Vite · Python (FastAPI) · PostgreSQL · Docker Compose.
См. [архитектуру](docs/architecture.md).

## Запуск

Требования: Docker и Docker Compose v2. Сейчас готовы вход, профиль и мероприятия.

```bash
cp .env.example .env
docker compose up --build
```

При старте контейнер `api` применяет миграции БД. Контейнер `worker` — фоновый процесс: раз в `WORKER_INTERVAL_SECONDS` (по умолчанию 300 с) создаёт напоминания «оцените участников», когда открывается окно отзывов; его журнал — `docker compose logs worker`. Frontend (dev-сервер Vite) проксирует `/api` в контейнер `api`, поэтому в браузере всё работает на одном адресе.

| Сервис | Адрес |
|---|---|
| **Сайт** | http://localhost:5173 |
| API | http://localhost:8000/api |
| Документация API (Swagger) | http://localhost:8000/api/docs |
| PostgreSQL | localhost:5432 (логин/пароль из `.env`) |

Остановка (`-v` дополнительно удаляет данные БД):

```bash
docker compose down
```

### Вход в разработке

SMS не отправляются. При `AUTH_TEST_ENDPOINTS=true` сайт показывает код входа прямо на экране ввода кода (оранжевая подсказка «Тестовый режим»). При `false` подсказки нет.

Через API код можно получить тестовой ручкой (работает только при `AUTH_TEST_ENDPOINTS=true`):

1. `POST /api/auth/code` с `{"phone": "+79991234567"}`
2. `GET /api/auth/test/code?phone=%2B79991234567` — вернёт код
3. `POST /api/auth/verify` с телефоном и кодом — вернёт `access_token` и `refresh_token`
4. Передавайте `Authorization: Bearer <access_token>`; сначала заполните профиль через `PATCH /api/profile` (`name`, `birth_date`)

Телефоны администраторов задаются в `ADMIN_PHONES` (через запятую).

### Мероприятия в интерфейсе

После входа открывается главная — список мероприятий с вкладками «Найти компанию», «Участвую» и «Организую» (в двух последних есть прошедшие), фильтрами по категории и датам.

1. «Создать мероприятие» в шапке открывает окно создания; после сохранения откроется страница мероприятия.
2. Чтобы проверить запись, войдите вторым пользователем (другой номер, например в другом браузере или приватном окне) и нажмите «Записаться» на странице мероприятия.
3. Автор на странице своего мероприятия может редактировать его на месте, удалить и исключить участников.
4. Над списком — поиск по названию, фильтры по категории, датам и свободным местам и быстрые фильтры «Есть свободные места» и «На этой неделе». Обложка карточки — основное фото мероприятия, а без фото — картинка категории.
5. К мероприятию можно прикрепить до 10 фото (JPEG, PNG, WebP до 2 МБ) в окне создания или в режиме редактирования; первое — основное. Фото сохраняются по «Создать»/«Сохранить» и показываются галереей в окне мероприятия.
6. Профиль — страница `/users/<id>` (пункт «Профиль» в меню): аватар, обложка, «О себе», интересы, город и счётчики мероприятий. Профили организатора и участников открываются из окна мероприятия; чужой профиль виден тем, кто был с человеком на одном мероприятии.
7. Город мероприятия обязателен: в окне создания по умолчанию подставляется город из профиля.
8. Колокольчик в шапке — уведомления: об изменении и удалении мероприятия, исключении, записи и отказе участников (организатору) и напоминание оценить участников. Точка на колокольчике — есть непрочитанные; открытие панели отмечает их прочитанными.

Ручки API (`GET /api/categories` и картинка категории `GET /api/categories/{id}/covers/{cover_id}`, `/api/events` с параметрами `scope`, `period` и `q`, `join`, `leave`, участники, фото `PUT /api/events/{id}/photos` и `GET /api/events/{id}/photos/{photo_id}` с `?size=thumb` для уменьшенной копии, города `GET /api/cities`, профиль `GET /api/profile/{id}`, аватар и обложка `PUT`/`DELETE /api/profile/avatar|cover` и `GET /api/users/{id}/images/{image_id}`, уведомления `GET /api/notifications`, `GET /api/notifications/unread-count`, `POST /api/notifications/read`) с примерами — в Swagger: http://localhost:8000/api/docs.

## Тесты и проверки

Тесты работают на отдельной БД `app_test` в контейнере `db`:

```bash
docker compose run --rm api pytest
```

Линтер, форматирование и типы:

```bash
docker compose run --rm api sh -c "ruff check . && ruff format --check . && mypy"
```

> БД `app_test` создаётся init-скриптом при первой инициализации тома. Если том `db-data` был создан раньше, пересоздайте его: `docker compose down -v`.

Frontend — тесты (Vitest), линтер, форматирование и типы:

```bash
docker compose run --rm web npm test
```

```bash
docker compose run --rm web sh -c "npm run lint && npm run format:check && npm run typecheck"
```

> `node_modules` фронтенда живут внутри образа `web`. После изменения `web/package.json` пересоберите его: `docker compose build web` (при необходимости с `docker compose up -d --renew-anon-volumes web`).

## 1. О приложении

Финансовый планер помогает вести личные финансы: он сводит в одно место счета, доходы и расходы, месячные бюджеты по категориям и цели накопления. Проект разрабатывается исключительно в учебных целях.

## 4. Функции

1. Одна команда Docker Compose поднимает три сервиса: PostgreSQL 18, API на Django и интерфейс на Vite. Сервисы стартуют по очереди: API ждёт готовую базу, а интерфейс ждёт готовый API.
2. При каждом запуске API применяет миграции Django к базе.
3. Маршрут `GET /api/health` отвечает кодом 200, когда база доступна, и кодом 503, когда нет. В ответе версии Python, Django и PostgreSQL и время запроса к базе в миллисекундах.
4. Стартовая страница сразу проверяет API и базу и показывает состояние каждого сервиса, версии и время ответа. Кнопка «Проверить снова» повторяет проверку.
5. Интерфейс обращается к API через прокси Vite по своему же адресу, поэтому настраивать CORS не нужно.
6. Django Ninja строит описание API в формате OpenAPI и страницу документации `/api/docs`.
7. В режиме watch Docker Compose сразу переносит изменённые файлы в контейнеры, а после правки зависимостей или Dockerfile пересобирает образ.
8. Два теста Django проверяют ответ `/api/health` при доступной и при недоступной базе.

## 5. Как пользоваться

Интерфейс открывается по адресу http://localhost:5173. На странице три карточки: «Интерфейс», «API» и «База данных», и у каждой своя метка состояния.

| Метка | Что значит |
| --- | --- |
| Проверка | Проверка ещё идёт |
| Работает | Сервис отвечает |
| Нет связи | Сервис не ответил или ответил ошибкой |
| Неизвестно | Состояние базы неизвестно, потому что недоступен сам API |

Строка над карточками подводит итог и показывает время последней проверки. Кнопка «Проверить снова» запускает проверку заново.

Документация API лежит по адресу http://localhost:8000/api/docs, там же каждый маршрут можно вызвать прямо из браузера. Для входа в админку Django нужно перейти по адресу http://localhost:8000/admin/. Если суперпользователь не создан, нужно выполнить команду:

```bash
docker compose exec api python manage.py createsuperuser
```

Если контейнер базы остановлен, проверка занимает около 8 секунд: столько Docker ищет имя `db`, прежде чем ответить, что его нет. После этого карточка «База данных» показывает «Нет связи». Когда база снова запущена, API возвращается в состояние `healthy` в течение 10–20 секунд.

## 6. Сборка и запуск

Для сборки нужны Docker Desktop (на Windows с WSL 2), Docker Compose 2.22 или новее и Git. Инструменты Node.js, Python и uv на компьютере не нужны, так как всё собирается и работает в контейнерах Docker.

Все команды ниже выполняются в папке `finance-planner`. Сначала из образца создаётся файл переменных окружения. В Git он не попадает, а значения `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD` в нём нужно заменить своими:

```bash
cp config/.env.example config/.env
```

Длинную случайную строку для ключа или пароля можно получить так:

```bash
docker run --rm python:3.14-slim python -c "import secrets; print(secrets.token_urlsafe(50))"
```

Запуск с живой синхронизацией файлов. Логи выводятся прямо в терминал:

```bash
docker compose up --build --watch
```

Запуск в фоне. Команда ждёт, пока база и API станут `healthy`:

```bash
docker compose up -d --build --wait
```

Проверка состояния и ответа API:

```bash
docker compose ps
curl http://127.0.0.1:8000/api/health
```

Тесты Django и проверка типов со сборкой интерфейса:

```bash
docker compose exec api python manage.py test
docker compose run --rm --no-deps web npm run build
```

Остановка сервисов. Данные базы остаются в томе `postgres_data`:

```bash
docker compose down
```

Команда `docker compose down -v` удаляет и том с данными базы. Она нужна, например, после смены `POSTGRES_PASSWORD`: пароль задаётся при первом создании базы и сам не меняется.

Новая зависимость добавляется в `pyproject.toml` или `package.json`, после чего lock-файл пересобирается одноразовым контейнером. Команды ниже для PowerShell:

```powershell
docker run --rm -v "${PWD}/api:/app" -w /app python:3.14-slim sh -c "pip install --quiet --root-user-action=ignore uv==0.13.5 && uv lock"
docker run --rm -v "${PWD}/web:/app" -w /app node:24-alpine npm install --package-lock-only --no-audit --no-fund
```

После этого достаточно `docker compose up --build`.

## 7. Конфигурация

Переменные задаются в файле `config/.env`, образец лежит в `config/.env.example`. **Для переменных (например, пароль, секреты и тому подобные), имеющих значение `REPLACE-THIS`, требуется ввести собственные значения**.

| Переменная | Назначение | Значение в образце |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | Секретный ключ Django для подписи сессий и токенов CSRF | `REPLACE-THIS` |
| `DJANGO_DEBUG` | Режим отладки: подробные страницы ошибок | `true` |
| `DJANGO_ALLOWED_HOSTS` | Имена хостов, на которые отвечает Django, через запятую | `localhost,127.0.0.1` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Адреса интерфейса, которым разрешены запросы `POST`, `PUT`, `PATCH` и `DELETE` | `http://localhost:5173,http://127.0.0.1:5173` |
| `DJANGO_TIME_ZONE` | Часовой пояс для дат и времени | `Asia/Yekaterinburg` |
| `POSTGRES_DB` | Имя базы данных | `finance_planner` |
| `POSTGRES_USER` | Пользователь базы данных | `finance_planner` |
| `POSTGRES_PASSWORD` | Пароль пользователя базы данных | `REPLACE-THIS` |
| `POSTGRES_HOST` | Адрес базы для API | `db` |
| `POSTGRES_PORT` | Порт базы | `5432` |

Остальное задано в `compose.yaml`:

| Параметр | Значение | Назначение |
| --- | :---: | --- |
| Порт интерфейса | 127.0.0.1:5173 | Vite, открыт только для этого компьютера |
| Порт API | 127.0.0.1:8000 | Django, открыт только для этого компьютера |
| Порт базы | не открыт | PostgreSQL доступна только внутри сети Docker |
| `API_PROXY_TARGET` | http://api:8000 | Куда Vite перенаправляет запросы `/api` |

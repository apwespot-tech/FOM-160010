# Spec Delta

## MODIFIED Requirements

### Requirement: Шапка приложения
Для авторизованного пользователя, в том числе с незаполненным профилем, шапка SHALL содержать: логотип, ведущий на `/`; ссылку «Мероприятия» на `/` (только от 640 px); кнопку «Создать мероприятие», открывающую окно создания (на мобильной ширине — иконка «+» с доступным именем); кнопку уведомлений с отметкой непрочитанного (см. «Отметка непрочитанных уведомлений»); кнопку меню профиля в виде скруглённого квадрата с инициалами, а без имени — с иконкой пользователя. Гостю показывается только логотип.

#### Scenario: Шапка на компьютере
- **WHEN** пользователь с заполненным профилем без непрочитанных уведомлений открывает любую страницу на ширине 1280 px
- **THEN** в шапке видны логотип, «Мероприятия», «Создать мероприятие» с иконкой «+» и подписью, кнопка уведомлений без точки и счётчика и скруглённый квадрат с инициалами пользователя

#### Scenario: Шапка на мобильном
- **WHEN** та же страница открыта на ширине 360 px
- **THEN** в шапке логотип и три кнопки-иконки, без горизонтальной прокрутки, у каждой кнопки область нажатия не меньше 44×44 px

#### Scenario: Шапка черновика
- **WHEN** пользователь с незаполненным профилем без имени открывает `/`
- **THEN** в шапке те же элементы, а на кнопке меню профиля — иконка пользователя вместо инициалов; в меню вместо имени показывается только телефон

#### Scenario: Шапка на странице входа
- **WHEN** гость открывает `/login`
- **THEN** в шапке только логотип

### Requirement: Уведомления
Кнопка уведомлений SHALL открывать панель «Уведомления» со списком до 20 последних уведомлений от новых к старым: текст (см. «Тексты уведомлений») и дата и время создания. Непрочитанные до открытия панели MUST быть выделены. Без уведомлений панель показывает «Уведомлений пока нет». Клик по уведомлению открывает `/events/:id` и закрывает панель; уведомление об удалённом мероприятии (`event.id` = `null`) не кликабельно.

#### Scenario: Открытие панели
- **WHEN** пользователь с тремя уведомлениями, из них одним непрочитанным, нажимает кнопку уведомлений
- **THEN** клиент запрашивает `GET /notifications` и показывает три уведомления, самое новое сверху, непрочитанное выделено

#### Scenario: Нет уведомлений
- **WHEN** у пользователя нет уведомлений и он открывает панель
- **THEN** панель показывает «Уведомлений пока нет»

#### Scenario: Переход к мероприятию
- **WHEN** пользователь нажимает уведомление о записи на его мероприятие
- **THEN** панель закрывается и открывается `/events/<id мероприятия>`

#### Scenario: Удалённое мероприятие
- **WHEN** в панели уведомление «Мероприятие «Прогулка» удалено»
- **THEN** уведомление не реагирует на нажатие и не выглядит ссылкой

#### Scenario: Ошибка загрузки
- **WHEN** `GET /notifications` завершается ошибкой
- **THEN** панель показывает «Не удалось загрузить уведомления», отметка непрочитанного на кнопке не снимается

## ADDED Requirements

### Requirement: Прочтение уведомлений при открытии панели
После успешной загрузки списка в панели клиент SHALL отправлять `POST /notifications/read` с `up_to`, равным `created_at` самого нового полученного уведомления, и снимать отметку непрочитанного на кнопке. При пустом списке отметка запроса не отправляется. Выделение непрочитанных в открытой панели сохраняется до её закрытия.

#### Scenario: Открытие с непрочитанными
- **WHEN** пользователь с двумя непрочитанными уведомлениями открывает панель
- **THEN** клиент отправляет `POST /notifications/read` с `up_to` самого нового уведомления, точка на кнопке исчезает, а два уведомления в панели остаются выделенными

#### Scenario: Повторное открытие
- **WHEN** пользователь закрывает панель и открывает её снова без новых уведомлений
- **THEN** ни одно уведомление не выделено

### Requirement: Тексты уведомлений
Клиент SHALL показывать каждое уведомление текстом по его типу, с названием мероприятия в кавычках «». Для `event_changed` текст MUST перечислять изменившиеся поля словами «время», «длительность», «город», «место», «название» через запятую в этом порядке, независимо от порядка в `changed_fields`. Для уведомлений об участнике текст MUST содержать его имя, кроме случая, когда получатель — сам участник.

#### Scenario: Удаление
- **WHEN** в панели уведомление `event_deleted` по мероприятию «Прогулка»
- **THEN** текст «Мероприятие «Прогулка» удалено»

#### Scenario: Запись
- **WHEN** организатор видит `participant_joined` по мероприятию «Мафия», где `participant` — Олег
- **THEN** текст «Новый участник «Мафия»: Олег»

#### Scenario: Отказ
- **WHEN** организатор видит `participant_left` по мероприятию «Мафия», где `participant` — Олег
- **THEN** текст «Отказ от участия в «Мафия»: Олег»

#### Scenario: Напоминание
- **WHEN** в панели уведомление `review_reminder` по мероприятию «Мафия»
- **THEN** текст «Оцените участников мероприятия «Мафия»»

#### Scenario: Изменилась длительность и город
- **WHEN** в панели уведомление `event_changed` с `changed_fields` = `["city_id", "duration_minutes"]` по мероприятию «Мафия»
- **THEN** текст «Изменилось мероприятие «Мафия»: длительность, город»

#### Scenario: Изменились время и место
- **WHEN** в панели уведомление `event_changed` с `changed_fields` = `["place", "starts_at"]` по мероприятию «Мафия»
- **THEN** текст «Изменилось мероприятие «Мафия»: время, место»

#### Scenario: Исключение глазами организатора
- **WHEN** организатор видит `participant_removed`, где `participant` — Анна
- **THEN** текст «Администратор исключил участника Анна из «Мафия»»

#### Scenario: Исключение глазами исключённого
- **WHEN** Анна видит `participant_removed`, где `participant` — она сама
- **THEN** текст «Вас исключили из мероприятия «Мафия»»

### Requirement: Отметка непрочитанных уведомлений
На кнопке уведомлений SHALL показываться точка без числа, если `unread_count` больше 0, а доступное имя кнопки MUST сообщать о непрочитанных («Уведомления, есть непрочитанные»). Авторизованный клиент, в том числе с незаполненным профилем, MUST запрашивать `GET /notifications/unread-count` после входа и загрузки приложения, при возвращении на вкладку и раз в 60 секунд, пока вкладка видима. Гость и скрытая вкладка запросов не отправляют.

#### Scenario: Есть непрочитанные
- **WHEN** сервер возвращает `unread_count` = 3
- **THEN** на кнопке уведомлений точка без числа

#### Scenario: Нет непрочитанных
- **WHEN** сервер возвращает `unread_count` = 0
- **THEN** точки на кнопке нет

#### Scenario: Периодическое обновление
- **WHEN** вкладка видима 60 секунд после предыдущего запроса
- **THEN** клиент снова запрашивает `GET /notifications/unread-count`

#### Scenario: Скрытая вкладка
- **WHEN** вкладка скрыта
- **THEN** периодические запросы не отправляются, а при возвращении на вкладку клиент сразу запрашивает число непрочитанных

#### Scenario: Выход
- **WHEN** пользователь выходит из приложения
- **THEN** запросы числа непрочитанных прекращаются, точка не показывается

#### Scenario: Ошибка запроса
- **WHEN** запрос числа непрочитанных завершается ошибкой
- **THEN** отметка остаётся прежней, сообщение об ошибке не показывается, следующий запрос — по расписанию

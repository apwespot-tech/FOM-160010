# Proposal

## Why

Все функции сервиса доступны только авторизованным пользователям, но в проекте пока нет ни backend, ни сущности пользователя. Это первая порция бизнес-логики: без пользователя и входа нельзя реализовать активности и участие.

## What Changes

- Создаётся каркас backend: Python-приложение API, PostgreSQL, миграции, запуск через Docker Compose, автотесты на реальной БД.
- Добавляется сущность пользователя: UUID-идентификатор, телефон (основной логин), имя, дата рождения, опциональные email, Telegram и ссылка на фото, набор ролей.
- Вход и регистрация по одноразовому коду, привязанному к телефону:
  - `POST /auth/code` — создать код для номера;
  - `GET /auth/test/code` — тестовая ручка, возвращает код из БД; работает только при включённом флаге окружения;
  - `POST /auth/verify` — проверить код, при первом входе создать пользователя-черновик, выдать access- и refresh-токены;
  - `POST /auth/refresh` — обменять refresh-токен на новую пару (ротация);
  - `POST /auth/logout` — отозвать refresh-токен.
- Профиль:
  - `GET /profile`, `PATCH /profile` — свой профиль;
  - `GET /profile/{id}` — чужой профиль, доступен себе и админу (403 остальным);
  - `PATCH /profile/{id}` — изменение чужого профиля админом, включая телефон.
- Роли `participant` и `organizer` выдаются каждому пользователю при создании; роль `admin` назначается по списку телефонов в переменной окружения.
- Пока профиль не заполнен (нет имени или даты рождения), пользователю доступны только ручки авторизации и своего профиля.
- В `docs/nfr.md` уточняется способ передачи токенов (в теле ответа, а не в cookie).

## Capabilities

### New Capabilities

- `auth`: вход и регистрация по одноразовому коду, выдача, обновление и отзыв токенов, назначение ролей, проверка доступа к защищённым ручкам.
- `user-profile`: данные пользователя, их валидация, заполнение профиля, правила просмотра и изменения своего и чужого профиля.

### Modified Capabilities

Нет.

## Impact

- Новый код: `api/` (приложение, модели, миграции, тесты), `compose.yaml`, `.env.example`.
- Новые зависимости backend: веб-фреймворк, ORM, драйвер PostgreSQL, библиотеки миграций, JWT и тестирования.
- Документация: `README.md` (реальные команды запуска и тестов), `docs/nfr.md`, `docs/architecture.md`.

## Вне scope

- Frontend.
- Реальная отправка SMS: код только сохраняется в БД.
- Загрузка файла фото: в этом изменении есть только опциональное поле со ссылкой.
- Смена телефона самим пользователем; управление ролями через API.
- Видимость профиля «связанным» пользователям (участникам общих активных событий) — добавится вместе с активностями и участием.
- Активности, каталог, участие.

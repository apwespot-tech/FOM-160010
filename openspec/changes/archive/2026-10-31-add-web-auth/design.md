# Design

## Context

Backend (`api/`) реализует вход по коду и профиль (спеки `auth`, `user-profile`): все ручки под `/api`, токены в теле ответа, access-токен в заголовке `Authorization: Bearer`, ошибки в формате `{"detail": {"code", "message"}}`, 429 с `retry_after`. Каталога `web/` нет. Мотивация — в proposal.md, требования — в `specs/web-app`.

Схема БД и API не меняются, миграций нет.

## Goals / Non-Goals

**Goals:**
- Каркас `web/`, на котором строятся следующие порции: слой API, сессия, гарды, тема и раскладка.
- Корректная работа с ротацией refresh-токенов при параллельных запросах.
- Визуальная база (тема PrimeVue и правила UI), которую не придётся переделывать при добавлении тёмной темы.

**Non-Goals:**
- Продакшен-сборка, nginx, SSR.
- Глобальная обработка оффлайн-режима и повтор запросов при сетевых ошибках.
- Интернационализация: интерфейс только на русском.

## Decisions

### Стек и инструменты
Vue 3 (Composition API, `<script setup lang="ts">`), TypeScript strict, Vite, vue-router, Pinia, PrimeVue 4.5 со styled-темой из `@primeuix/themes` 2.x, `primeicons` 7, русская локаль компонентов из `primelocale`.

Версии Prime-пакетов закреплены на последних мажорах с лицензией MIT: `primevue@^4.5`, `@primeuix/themes@^2`, `primeicons@^7`. Начиная с PrimeVue 5, `@primeuix/themes` 3 и `primeicons` 8 (июль 2026) пакеты распространяются по коммерческой PrimeUI License с обязательным лицензионным ключом. Переход на них — отдельное решение. Проверки — `vue-tsc`, ESLint (flat config: `eslint-plugin-vue`, `typescript-eslint`, `eslint-config-prettier`) и Prettier. Тесты — Vitest, jsdom и `@vue/test-utils`. Пакетный менеджер — npm с закоммиченным `package-lock.json`.

Компоненты не вызывают `fetch` напрямую: только через `src/api/` (`docs/rules.md`).

### Запуск и прокси
Сервис `web` в `compose.yaml`: образ `node:22-alpine`, `npm ci` при сборке, исходники монтируются в `/app`, `node_modules` — в анонимный том, чтобы монтирование их не перекрывало. Dev-сервер Vite слушает `0.0.0.0:5173` и проксирует `/api` на `VITE_API_PROXY_TARGET` (в compose — `http://api:8000`, по умолчанию — `http://localhost:8000` для локального `npm run dev`). Браузер видит фронт и API на одном origin, поэтому CORS не нужен и backend не меняется.

### Слой API
`apiFetch<T>(path, { method, body, auth })` добавляет префикс `/api`, JSON и заголовок `Authorization`. Ответ не-2xx превращается в `ApiError { status, code, message, retryAfter? }`. `code` берётся из `detail.code`, а для 422 Pydantic — `validation_error`.

**Single-flight refresh.** В модуле хранится `refreshPromise: Promise<string | null> | null`. При 401 на запрос с `auth: true`:
1. если `refreshPromise` нет, создаётся новый — он вызывает `POST /auth/refresh` и по завершении сбрасывает себя в `null`;
2. все запросы, получившие 401, ждут один и тот же промис;
3. если он вернул новый access-токен, исходный запрос повторяется один раз; повторный 401 не запускает новое обновление;
4. если вернул `null`, сессия очищается, и роутер уводит на `/login`.

Без этого второй параллельный запрос предъявил бы уже погашенный refresh-токен и получил 401 (ротация в спеке `auth`).

### Сессия
Pinia-стор `session`:
- `accessToken` — только в памяти;
- refresh-токен — в `localStorage` под ключом `ik.refreshToken`;
- `profile` — последний загруженный профиль.

`init()` выполняется один раз при первой навигации: если refresh-токен сохранён, стор обновляет токены и загружает профиль; при ошибке очищает сессию. `login(tokens)` сохраняет токены и загружает профиль. `logout()` вызывает `POST /auth/logout` (ошибку игнорирует) и очищает сессию.

Хранение refresh-токена в `localStorage` уязвимо для XSS. Для MVP это принято: альтернатива — httpOnly-cookie, требующая изменений backend.

### Маршруты и гард
| Путь | `meta` | Компонент |
|---|---|---|
| `/login` | `guest` | LoginView |
| `/onboarding` | `auth`, `incomplete` | OnboardingView |
| `/profile` | `auth`, `complete` | ProfileView |
| `/`, `/:pathMatch(.*)*` | — | редирект на `/profile` |

Глобальный `beforeEach` дожидается `session.init()`, затем: нет сессии и маршрут не `guest` → `/login`; сессия есть и профиль не заполнен → `/onboarding`; профиль заполнен и маршрут `guest` или `incomplete` → `/profile`.

### Вход
`LoginView` хранит шаг (`phone` | `code`), номер и дедлайн повторной отправки. `PhoneStep` отправляет номер; при 200 дедлайн = сейчас + 60 с, при 429 — сейчас + `retry_after`, и в обоих случаях открывается шаг кода. Затем `DevCodeHint` вызывает `getTestCode(phone)`: показывает код в `Message` с severity `warn` и подписью «Тестовый режим: SMS не отправляются», при любой ошибке не показывает ничего. `useCountdown(deadline)` пересчитывает оставшиеся секунды раз в 250 мс от `Date.now()`, поэтому таймер не уходит при неактивной вкладке.

`DevCodeHint` — единственное место, знающее о тестовой ручке. После подключения SMS удаляется он и `getTestCode`.

### Форма профиля
Логика формы вынесена в composable `useProfileForm`: состояние полей, валидация, дифф изменений, отправка, раскладка серверных ошибок. Поле даты — в компоненте `BirthDateInput`. Их используют два компонента:
- `ProfileForm` — форма онбординга (вертикальная, с подписями над полями);
- `ProfileCard` — карточка профиля с режимами просмотра и редактирования в одной раскладке (стандарт «Окна и карточки с данными» в `docs/rules.md`). Корень карточки — один и тот же `<form>`. В режиме редактирования в `dd` строк вместо текста рендерятся поля, имя в шапке заменяется полем с `aria-label`, телефон, аватар и возраст остаются текстом, а кнопка «Редактировать» на своём месте сменяется на «Сохранить» и «Отмена».

Поля и валидация: Поля: `InputText` для имени, `DatePicker` (`dateFormat="dd.mm.yy"`, `minDate` = 01.01.1900, `maxDate` = сегодня), `InputText` для email и Telegram. Правила валидации повторяют спеку `user-profile`. При сохранении форма сравнивает значения с исходными и отправляет только изменённые поля; пустое необязательное поле уходит как `null`. Серверные 422 и 409 раскладываются по полям через `ApiError.code`.

Дата преобразуется между `Date` и `YYYY-MM-DD` по локальным компонентам (`getFullYear/getMonth/getDate`), а не через `toISOString()`: иначе в часовых поясах восточнее UTC дата сдвигается на день назад.

### Тема и стиль
- `definePreset(Aura, …)`: `semantic.primary` — фиолетовая шкала (500 `#8B5CF6`, 600 `#7C3AED`, 700 `#6D28D9`), `colorScheme.light`: primary `{primary.700}`, hover `{primary.800}`, фон поверхностей `#FFFFFF` и `#F8F7FC`, границы `#E7E5EF`, текст `#1F1B2E` и `#6B6780`.
- Оранжевый акцент (`#F97316`, hover `#EA580C`) — CSS-переменные `--app-accent*`. Применяется к бейджам, подсказке с тестовым кодом и важным статусам, но не к основным кнопкам.
- `darkModeSelector: '.app-dark'` задаётся сейчас, но класс не включается: тёмная тема потом — это `colorScheme.dark` в пресете и переключатель.
- Без градиентов и эмодзи, иконки — только `primeicons`. Эти правила записываются в `docs/rules.md`, раздел «UI».
### Адаптивность
Вёрстка mobile-first: базовые стили рассчитаны на телефон, а более широкие экраны добавляются через `min-width` media queries. Брейкпоинты задаются CSS-переменными и константами в одном месте (`styles.css`) и совпадают со шкалой PrimeFlex/PrimeVue:

```text
  ширина:   360 ............ 639 | 640 ........ 1023 | 1024 ............ 1920
  режим:    mobile               | tablet            | desktop
  отступы:  16 px                | 24 px             | 32 px
  карточка: 100% ширины          | центр, max 480 px | центр, 420 px (вход/онбординг)
            (без рамки и тени)   | (с рамкой)        |        640 px (профиль)
  профиль:  аватар над данными   | аватар над данными| аватар слева, данные справа
  шапка:    «Выйти» — иконка     | иконка + текст    | иконка + текст
            с aria-label         |                   |
```

- Сетка — CSS Grid и Flexbox без фиксированных ширин в px внутри карточек. Длинные значения (email) переносятся через `overflow-wrap: anywhere`, поэтому горизонтальной прокрутки нет.
- Размеры зависят от ширины контейнера, а не от типа устройства. User-Agent не анализируется, поэтому поворот экрана и изменение размера окна обрабатываются без перезагрузки.
- Сенсорный ввод: минимальная высота полей и кнопок 44 px (через токены `formField` пресета). Телефон — `type="tel"`, `inputmode="tel"`, `autocomplete="tel"`. Код — `inputmode="numeric"`, `autocomplete="one-time-code"`, `maxlength="6"`.
- Дата рождения: на мобильной ширине — нативное `<input type="date">` с `min`/`max`. Оно открывает системный выбор даты (колесо), удобный на сенсорном экране. На планшете и компьютере — `DatePicker` PrimeVue с ручным вводом `ДД.ММ.ГГГГ`, чтобы не листать годы до 1990-х. Режима `touchUI` в PrimeVue 4 больше нет (он был в v3), а проп `breakpoint` разметку не меняет. Значение формы одно (`Date`), поэтому при смене ширины введённая дата сохраняется.
- Тосты на мобильной ширине показываются по центру сверху во всю ширину, на остальных — в правом верхнем углу.
- `<meta name="viewport" content="width=device-width, initial-scale=1">`. Масштабирование не запрещается (ради доступности), а размер шрифта в полях не меньше 16 px, чтобы iOS не увеличивала страницу при фокусе.

Проверка: unit-тесты проверяют атрибуты полей и реакцию на брейкпоинт через замоканный `matchMedia`. Отсутствие горизонтальной прокрутки и вид на 360, 768 и 1280 px проверяются вручную в браузере.

### Раскладка
Шапка с названием «Ищу компанию» и кнопкой «Выйти» (только при сессии), контейнер страниц. Размеры карточек — по таблице из раздела «Адаптивность».

### Тестирование
Vitest с jsdom. Хелпер `mountWithPrimeVue` устанавливает PrimeVue с темой в режиме `unstyled: false`. `fetch` подменяется `vi.fn`, время — `vi.useFakeTimers()`. Тесты по требованиям спеки: гард (через роутер в memory history), шаги входа, подсказка с кодом, таймер, валидация и дифф формы, сессия, single-flight (два параллельных запроса с 401 → один вызов `/auth/refresh`), выход.

## Risks / Trade-offs

- [Refresh-токен в `localStorage` доступен скриптам при XSS] → Vue экранирует вывод, `v-html` не используется. При появлении реального прода перейти на httpOnly-cookie отдельным изменением backend и frontend.
- [Лишний запрос `GET /auth/test/code` с ответом 404 в рабочем окружении] → один запрос на вход, без побочных эффектов. Исчезнет вместе с `DevCodeHint`.
- [Бандл PrimeVue тяжелее] → компоненты импортируются точечно, а не глобальной регистрацией всех.
- [Расхождение клиентской и серверной валидации] → сервер остаётся источником правды: его ошибки 422 и 409 всегда показываются у полей.
- [Отсутствие горизонтальной прокрутки нельзя надёжно проверить в jsdom: в нём нет вёрстки] → ручная проверка на трёх ширинах в задаче итоговой проверки. Автоматическая визуальная проверка появится вместе с E2E-тестами.
- [Анонимный том `node_modules` устаревает при изменении зависимостей] → после изменения `package.json` нужен `docker compose build web`. Это записывается в README.

## Migration Plan

Изменений БД и API нет. Откат — удаление сервиса `web` из compose и каталога `web/`.

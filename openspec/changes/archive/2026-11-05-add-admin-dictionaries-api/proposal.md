# Proposal

## Why

Справочники категорий и городов сейчас пополняются только миграциями. Чтобы добавить город для нового пользователя или переименовать категорию, нужен релиз. Администратор должен управлять справочниками сам, через API, без участия разработчиков.

## What Changes

- **Категории** (`events`), только администратору:
  - `POST /categories` — создать категорию: название, иконка и картинка (multipart);
  - `PATCH /categories/{id}` — изменить название и иконку;
  - `PUT /categories/{id}/cover` — заменить картинку (новый `cover_id`, прежняя картинка удаляется);
  - `DELETE /categories/{id}` — удалить категорию. Если на неё ссылаются мероприятия, ответ 409 `category_in_use`; интересы пользователей с этой категорией удаляются.
- **Города** (`cities`), только администратору:
  - `POST /cities`, `PATCH /cities/{id}` — создать и переименовать город;
  - `DELETE /cities/{id}` — удалить город. Если на него ссылаются мероприятия, ответ 409 `city_in_use`; город в профилях пользователей очищается.
- **Названия** категорий и городов уникальны без учёта регистра («Москва» и «москва» — конфликт 409 `category_name_taken` / `city_name_taken`). Пробелы по краям обрезаются.
- Утверждение спек «справочник пополняется только миграциями» заменяется: справочники меняются миграциями и администратором через API.
- **Документация**:
  - `docs/architecture.md`;
  - `docs/backlog.md`: убрать оба пункта «Управление категориями через API», а пункт «Добавление городов пользователями» уточнить: администратор добавлять города уже может.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `events`: «Справочник категорий» (меняется не только миграциями); новые требования — создание, изменение, замена картинки и удаление категории администратором, уникальность названия категории.
- `cities`: «Справочник городов» (меняется не только миграциями); новые требования — создание, переименование и удаление города администратором, уникальность названия города.

## Impact

- Backend:
  - новые ручки в `api/app/routers/categories.py` и `cities.py`;
  - сервис справочников;
  - схемы запросов;
  - миграция `0006`: уникальность `lower(name)` вместо `uq_categories_name` и `uq_cities_name`;
  - перевод нарушений внешних ключей при одновременном удалении в 409 и 422;
  - тесты.
- Frontend не меняется. Справочники загружаются один раз за сессию, поэтому изменения видны пользователям после перезагрузки страницы.
- API совместимо: появляются только новые ручки, существующие ответы не меняются.

## Вне scope

- Админский интерфейс во фронтенде.
- Архивация или скрытие категорий и городов вместо удаления; перенос мероприятий в другую категорию или город при удалении.
- Порядок категорий, отличный от `id`; сортировка городов не по алфавиту.
- Проверка, что иконка существует в primeicons: проверяется только формат `pi-...`.
- Добавление городов обычными пользователями.

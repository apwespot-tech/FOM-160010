## MODIFIED Requirements

### Requirement: Справочник категорий
Система SHALL хранить категории мероприятий в отдельном справочнике: `id` (целое число), `name` (строка, уникальная без учёта регистра), `icon` (имя иконки primeicons, например `pi-video`) и обязательную картинку категории. Категорию без картинки и без иконки MUST NOT быть возможно сохранить — это ограничение БД. Изначально справочник содержит «Настольные игры», «Прогулки», «Спорт», «Кино»; его меняют миграции и администратор через API. Система SHALL по `GET /categories` возвращать все категории, упорядоченные по `id`, любому авторизованному пользователю, в том числе с незаполненным профилем; категория в ответах (справочник и поле `category` мероприятия) содержит `id`, `name`, `icon` и `cover_id`.

#### Scenario: Получение категорий
- **WHEN** пользователь с заполненным профилем вызывает `GET /categories`
- **THEN** система отвечает 200 со списком категорий, в котором есть «Настольные игры», «Прогулки», «Спорт» и «Кино», у каждой есть `id`, `name`, непустой `icon` и `cover_id`

#### Scenario: Черновик запрашивает категории
- **WHEN** пользователь с незаполненным профилем вызывает `GET /categories`
- **THEN** система отвечает 200 с тем же списком категорий

#### Scenario: Категория в мероприятии
- **WHEN** пользователь получает мероприятие категории «Кино»
- **THEN** поле `category` содержит `id`, `name` = «Кино», `icon` и `cover_id` той же категории, что и в `GET /categories`

#### Scenario: Категория без картинки
- **WHEN** в справочник пытаются добавить категорию без картинки или без иконки
- **THEN** БД отклоняет запись

#### Scenario: Новая категория в конце списка
- **WHEN** администратор создал категорию «Музеи»
- **THEN** `GET /categories` возвращает её последней

## ADDED Requirements

### Requirement: Права на изменение справочника категорий
Ручки создания, изменения, замены картинки и удаления категории SHALL быть доступны только администратору. Без токена система MUST отвечать 401, пользователю с незаполненным профилем — 403 `profile_incomplete`, остальным не-администраторам — 403 `forbidden`, при этом справочник не меняется.

#### Scenario: Обычный пользователь создаёт категорию
- **WHEN** пользователь без роли `admin` вызывает `POST /categories` с корректными полями
- **THEN** система отвечает 403 и категория не создаётся

#### Scenario: Без токена
- **WHEN** клиент вызывает `DELETE /categories/{id}` без токена
- **THEN** система отвечает 401 и категория остаётся

### Requirement: Создание категории
Система SHALL по `POST /categories` (multipart: `name`, `icon`, файл `file`) создавать категорию и отвечать 201 с её представлением. `name` — 1–50 символов после обрезки пробелов по краям; `icon` — формат `pi-` и строчные латинские буквы, цифры и `-`; файл — JPEG, PNG или WebP до 2 МБ, тип определяется по содержимому (иначе 422 `photo_too_large` или `photo_invalid`). Картинка сохраняется с уменьшенной копией, как картинки категорий.

#### Scenario: Создание категории
- **WHEN** администратор отправляет `POST /categories` с `name` = « Музеи », `icon` = `pi-building` и JPEG
- **THEN** система отвечает 201 с `name` = «Музеи», `icon` = `pi-building` и новым `cover_id`, картинка доступна по `GET /categories/{id}/covers/{cover_id}` и с `size=thumb`

#### Scenario: Название на границе длины
- **WHEN** администратор создаёт категорию с названием из 50 символов, а затем из 51
- **THEN** первая создаётся, на вторую система отвечает 422

#### Scenario: Пустое название или неверная иконка
- **WHEN** администратор передаёт `name` из одних пробелов или `icon` = `video`
- **THEN** система отвечает 422 и категория не создаётся

#### Scenario: Без картинки
- **WHEN** администратор отправляет `POST /categories` без файла
- **THEN** система отвечает 422 и категория не создаётся

#### Scenario: Файл на границе размера
- **WHEN** администратор загружает картинку ровно 2 МБ, а затем 2 МБ + 1 байт
- **THEN** первая категория создаётся, на вторую система отвечает 422 `photo_too_large`

#### Scenario: Не картинка
- **WHEN** администратор загружает текстовый файл с именем `cover.jpg`
- **THEN** система отвечает 422 `photo_invalid` и категория не создаётся

### Requirement: Уникальность названия категории
Название категории SHALL быть уникально без учёта регистра. Создание или переименование в занятое название MUST отклоняться с 409 `category_name_taken`; при одновременных попытках занять одно название успешна MUST быть ровно одна.

#### Scenario: Занятое название в другом регистре
- **WHEN** администратор создаёт категорию «кино», а «Кино» уже есть
- **THEN** система отвечает 409 `category_name_taken`

#### Scenario: Смена регистра своего названия
- **WHEN** администратор переименовывает «Кино» в «КИНО»
- **THEN** система отвечает 200 и название меняется

#### Scenario: Одновременное создание
- **WHEN** два запроса одновременно создают категорию «Музеи»
- **THEN** один получает 201, другой 409 `category_name_taken`, категория «Музеи» одна

### Requirement: Изменение категории
Система SHALL по `PATCH /categories/{id}` частично обновлять `name` и `icon` с той же валидацией, что при создании, и возвращать обновлённую категорию. Очистить их значением `null` нельзя (422); другие поля MUST отклоняться с 422. Для несуществующего `id` — 404. Мероприятия категории показывают новое название и иконку.

#### Scenario: Переименование
- **WHEN** администратор отправляет `PATCH /categories/{id}` категории «Кино» с `name` = «Кино и сериалы»
- **THEN** система отвечает 200, а мероприятия этой категории возвращают `category.name` = «Кино и сериалы»

#### Scenario: Попытка очистить иконку
- **WHEN** администратор отправляет `PATCH` с `icon: null`
- **THEN** система отвечает 422 и иконка не меняется

#### Scenario: Несуществующая категория
- **WHEN** администратор отправляет `PATCH /categories/999`
- **THEN** система отвечает 404

### Requirement: Замена картинки категории
Система SHALL по `PUT /categories/{id}/cover` (multipart, один файл) заменять картинку категории и возвращать категорию с новым `cover_id`. Файл проверяется как при создании. Прежняя картинка MUST удаляться: её адрес отвечает 404. Для несуществующего `id` — 404. При одновременных заменах итоговая картинка — одна из загруженных, лишних картинок не остаётся.

#### Scenario: Замена картинки
- **WHEN** администратор загружает новую картинку для категории «Спорт»
- **THEN** система отвечает 200 с новым `cover_id`, по прежнему `cover_id` — 404

#### Scenario: Некорректный файл
- **WHEN** администратор загружает файл 3 МБ
- **THEN** система отвечает 422 `photo_too_large`, `cover_id` не меняется

#### Scenario: Одновременная замена
- **WHEN** администратор одновременно отправляет две замены картинки одной категории
- **THEN** обе успешны, у категории одна из двух картинок, вторая удалена

### Requirement: Удаление категории
Система SHALL по `DELETE /categories/{id}` удалять категорию, на которую не ссылается ни одно мероприятие (в том числе прошедшее), вместе с её картинкой и отвечать 204; интересы пользователей с этой категорией удаляются. Если мероприятия есть — 409 `category_in_use`, категория не меняется. Для несуществующего `id` — 404.

#### Scenario: Удаление неиспользуемой категории
- **WHEN** у категории нет мероприятий, а у пользователя она в интересах
- **THEN** система отвечает 204, категории нет в `GET /categories`, у пользователя её нет в интересах, адрес её картинки отвечает 404

#### Scenario: Категория с прошедшим мероприятием
- **WHEN** у категории есть только одно уже прошедшее мероприятие
- **THEN** система отвечает 409 `category_in_use`

#### Scenario: Удаление одновременно с созданием мероприятия
- **WHEN** администратор удаляет неиспользуемую категорию, а другой пользователь одновременно создаёт в ней мероприятие
- **THEN** либо удаление получает 409 `category_in_use` и мероприятие создаётся, либо категория удаляется и создание получает 422 `category_not_found`

#### Scenario: Удаление одновременно с выбором интереса
- **WHEN** администратор удаляет категорию, а пользователь одновременно добавляет её в интересы
- **THEN** категория удаляется, а в интересах пользователя её в итоге нет: либо его запрос получает 422 `category_not_found`, либо сохраняется и интерес удаляется вместе с категорией

# Design

## Context

- Категории: таблица `categories (id, name)` заполняется миграцией `0002`, ручки изменения нет. `CategoryOut` — `id`, `name`; frontend кеширует справочник в `useCategories`.
- Фото мероприятий (`add-event-photos`): `event_photos` + `event_photo_data (photo_id, data)`, обработка в `services/photo_processing.py` (Pillow), отдача `GET /events/{id}/photos/{photo_id}` с `private, immutable`; на frontend — `apiFetchBlob` и кеш `usePhotoUrl` по `id`.
- Каталог: `EventsView.vue` (заголовок, вкладки, сетка), `EventFilters.vue` (категория, даты, места; на мобильном — окно «Фильтры»), `EventListCard.vue` (текстовая карточка), состояние в адресе — `useEventListQuery.ts`.
- Шапка: `AppHeader.vue`, `NotificationsButton.vue`, `ProfileMenu.vue` (круглая кнопка с инициалами).
- Шрифт `primeicons.ttf` и `primeicons.css` (MIT) лежат в `web/node_modules/primeicons/`.

## Goals / Non-Goals

**Goals:**
- Обязательность картинки категории гарантирована БД, а не кодом.
- Каталог не скачивает исходные фото: только копии до 800 px.
- Картинки категорий воспроизводимы: генератор в репозитории, результат детерминирован.

**Non-Goals:**
- Адаптивные размеры (`srcset`), ленивая подгрузка за пределами экрана (кроме `loading="lazy"` у `<img>`), прогрессивные превью.
- Полнотекстовый поиск, индексы `pg_trgm` — данных мало, `ILIKE` достаточно.

## Decisions

### 1. Схема БД и миграция `0004_catalog_covers`

```
 category_covers                            categories
 +--------------------------------+         +-----------------------------------+
 | id           uuid PK           |<--------| cover_id  uuid NOT NULL FK RESTRICT|
 | content_type varchar(20) CHECK |         | icon      varchar(40) NOT NULL    |
 | data         bytea NOT NULL    |         |           CHECK icon ~ '^pi-[a-z0-9-]+$'
 | thumb        bytea NOT NULL    |         | id, name                          |
 | created_at   timestamptz       |         +-----------------------------------+
 +--------------------------------+

 event_photo_data: + thumb bytea NOT NULL   (WebP, ширина <= 800)
```

Шаги `upgrade`:
1. Создать `category_covers`.
2. Добавить `categories.icon` и `categories.cover_id` как nullable.
3. Для каждой из четырёх категорий (по `name`) вставить картинку из `api/migrations/assets/category_covers/<slug>.webp` (полная) и её уменьшенную копию, проставить `cover_id` и `icon`.
4. Сделать `icon` и `cover_id` `NOT NULL`, добавить FK и `CHECK`. Если в БД есть категория, которой нет в списке миграции, шаг 4 упадёт — это намеренно: картинка обязательна.
5. Добавить `event_photo_data.thumb` nullable, заполнить для всех существующих фото, сделать `NOT NULL`.

Миграция не импортирует код приложения (`app.*`): функция уменьшения — внутри файла миграции, чтобы будущие изменения сервиса не ломали историю миграций. `downgrade` удаляет `thumb`, `cover_id`, `icon` и таблицу `category_covers`.

`ON DELETE RESTRICT` у `cover_id`: картинку нельзя удалить, пока на неё ссылается категория. Байты лежат в отдельной таблице — запросы мероприятий читают только `cover_id`.

Альтернатива — колонки `cover bytea` прямо в `categories`: проще, но каждый `SELECT` категорий (в том числе JOIN каталога) рисковал бы тащить байты, а замена картинки не давала бы нового `id` для кеша.

### 2. Картинки категорий: генератор и готовые файлы

`api/scripts/generate_category_covers.py` (запускается вручную, в рантайме не нужен):
- аргументы: путь к `primeicons.ttf` и `primeicons.css` (из `web/node_modules/primeicons`), каталог вывода;
- код глифа берётся из CSS (`.pi-video:before { content: "\e9.." }`), рисуется белым по центру, ~40% высоты, на сплошном фоне 1200×675, без текста и градиентов, сохраняется WebP `quality=85`;
- набор: Настольные игры — `pi-th-large`, `#7c3aed`; Прогулки — `pi-map`, `#16a34a`; Спорт — `pi-bolt`, `#ea580c`; Кино — `pi-video`, `#475569`.

Результат коммитится в `api/migrations/assets/category_covers/` (4 файла по нескольку КБ) вместе с `README.md` об источнике глифов (primeicons, MIT) и командой пересборки. Миграция читает готовые файлы, поэтому не зависит от наличия шрифта в образе `api`.

### 3. Уменьшенные копии

- `photo_processing.process_photo` возвращает также `thumb`: из уже повёрнутого и очищенного изображения `Image.thumbnail((800, 10_000))` (только уменьшение), перевод в RGB/RGBA, WebP `quality=80`, без метаданных. Копия сохраняется в `event_photo_data.thumb` в той же транзакции.
- Ручки фото и картинки категории принимают `size: Literal["full", "thumb"] = "full"` (иначе 422), `thumb` всегда `image/webp`. Заголовки кеша прежние.
- Размер 800 px выбран под карточку ~380 px на экране с плотностью 2×; WebP 800×450 — порядка 40–80 КБ против мегабайт оригинала.

### 4. Картинка категории в API

- `CategoryOut` получает `icon` и `cover_id`; `_view_query` уже соединяет `Category` — добавляются `Category.icon`, `Category.cover_id`, `EventView` и `EventOut.from_view` передают их в `category`.
- `GET /categories/{id}/covers/{cover_id}`: `SELECT data|thumb, content_type FROM category_covers JOIN categories ON categories.cover_id = category_covers.id WHERE categories.id = :id AND category_covers.id = :cover_id`; нет строки — 404 `cover_not_found`. Адрес содержит `cover_id`, поэтому `immutable` безопасен.

### 5. Поиск `q`

- В роутере: `q: Annotated[str | None, Query(max_length=100)]`; в сервисе `q.strip()`, пустая строка — без условия.
- Условие: `Event.title.ilike(f"%{escaped}%", escape="\\")`, где в `escaped` экранированы `\`, `%`, `_`. Добавляется в общий список `conditions`, поэтому `total` и вкладки учитывают его автоматически.
- PostgreSQL `ILIKE` регистронезависим и для кириллицы (локаль БД — UTF-8), это проверяется тестом.

### 6. Frontend: данные и кеш картинок

- `api/events.ts`: `Category` + `icon`, `cover_id`; `fetchEventPhoto(eventId, photoId, size)`; `fetchCategoryCover(categoryId, coverId, size)`; `EventListParams.q`.
- `usePhotoUrl.ts` обобщается до кеша по ключу: `photo:<id>:<size>` и `cover:<cover_id>:<size>`; `loadPhotoUrl(eventId, photoId, size)` и `loadCategoryCoverUrl(category, size)`; очистка при выходе — та же. Галерея окна мероприятия продолжает брать `full` для основного фото и просмотра, миниатюры галереи переходят на `thumb`.
- `useEventListQuery`: в состоянии `search` (адрес `q`, обрезка пробелов, до 100 символов); `activeFilters` (число на кнопке «Фильтры») — только категория, даты, места; новый `hasActive` = поиск или любой фильтр, для «Сбросить» и пустого состояния.
- Дата «этой недели» — чистая функция `currentWeekRange(today)` в `utils/dates.ts` (понедельник — начало недели, от сегодня до воскресенья); подсветка быстрых фильтров — вычисление из состояния, без своего хранения.

### 7. Frontend: компоненты

- `EventFilters.vue` → панель-карточка: строка полей (`InputText` с иконкой поиска и локальной задержкой 300 мс; категория; даты; места) и строка «Быстрый фильтр: [чипы]  ...  Сбросить». Чипы — кнопки с `aria-pressed`. На мобильном: поиск и чипы вне окна, остальные поля — в окне «Фильтры (N)».
- `CategoryTag.vue` — тег категории с иконкой; неизвестное или некорректное имя иконки (не из списка используемых в проекте) заменяется на `pi-tag`.
- `EventCover.vue` — обложка 16:9: цепочка «копия основного фото → копия картинки категории → нейтральный фон с иконкой категории»; `loading="lazy"`, `decoding="async"`.
- `EventListCard.vue` — по макету: обложка с `CategoryTag` (слева сверху), отметкой (справа сверху: «Вы организатор» / «Вы записаны» — акцентный оранжевый, «Мест нет» — тёмная плашка), датой на плашке (слева снизу, `rgb(0 0 0 / 0.55)`); тело — название, возраст, место, строка мест и статус, полоса заполненности (`role="progressbar"`, `aria-valuenow`): основной цвет, акцент — если записан или организатор, серый — если заполнено.
- `EventsView.vue` — подзаголовок; сетка 1 / 2 (от 640) / 3 (от 1024) колонки.
- Шапка: `ProfileMenu` — кнопка-квадрат 40×40 со скруглением 10 px, светлый фон основного цвета, инициалы; «Создать мероприятие» — основная кнопка с иконкой; колокольчик — текстовая кнопка без отметки. Левая часть шапки не меняется.

## Risks / Trade-offs

- [Миграция с заполнением копий для всех фото может идти долго на большой БД] → у MVP фото немного; обработка построчно, без загрузки всех байтов в память сразу.
- [Новая категория, добавленная миграцией без картинки, уронит миграцию] → это и есть требование; в `docs/architecture.md` описано, как добавить категорию (картинка + иконка в той же миграции, генератор для картинки).
- [`ILIKE '%...%'` без индекса — полный просмотр таблицы] → допустимо при текущем объёме; при росте — `pg_trgm` GIN-индекс.
- [Сгенерированные картинки выглядят беднее фото с макета] → осознанный выбор пользователя; замена — новой миграцией с новыми `cover_id`, кеш браузера обновится сам.
- [Чип «На этой неделе» в воскресенье вечером даёт почти пустой диапазон] → так определено в спеке; пользователь видит выбранные даты в поле.

## Migration Plan

1. `docker compose up --build` применяет `0004`: категории получают иконки и картинки, существующие фото — копии.
2. Откат: `alembic downgrade 0003` удаляет новые поля и таблицу; frontend без `icon`/`cover_id` показывает тег без иконки и нейтральную обложку.

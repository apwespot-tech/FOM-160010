# Spec Delta

## MODIFIED Requirements

### Requirement: Справочник категорий
Система SHALL хранить категории мероприятий в отдельном справочнике: `id` (целое число), `name` (уникальная строка), `icon` (имя иконки primeicons, например `pi-video`) и обязательную картинку категории. Категорию без картинки и без иконки MUST NOT быть возможно сохранить — это ограничение БД. Изначально справочник содержит «Настольные игры», «Прогулки», «Спорт», «Кино». Система SHALL по `GET /categories` возвращать все категории, упорядоченные по `id`; категория в ответах (справочник и поле `category` мероприятия) содержит `id`, `name`, `icon` и `cover_id`.

#### Scenario: Получение категорий
- **WHEN** пользователь с заполненным профилем вызывает `GET /categories`
- **THEN** система отвечает 200 со списком категорий, в котором есть «Настольные игры», «Прогулки», «Спорт» и «Кино», у каждой есть `id`, `name`, непустой `icon` и `cover_id`

#### Scenario: Черновик запрашивает категории
- **WHEN** пользователь с незаполненным профилем вызывает `GET /categories`
- **THEN** система отвечает 403 с кодом `profile_incomplete`

#### Scenario: Категория в мероприятии
- **WHEN** пользователь получает мероприятие категории «Кино»
- **THEN** поле `category` содержит `id`, `name` = «Кино», `icon` и `cover_id` той же категории, что и в `GET /categories`

#### Scenario: Категория без картинки
- **WHEN** в справочник пытаются добавить категорию без картинки или без иконки
- **THEN** БД отклоняет запись

### Requirement: Получение фото мероприятия
Система SHALL по `GET /events/{id}/photos/{photo_id}` отдавать содержимое фото с его типом (`image/jpeg`, `image/png` или `image/webp`) любому пользователю, которому доступен просмотр мероприятия, в том числе после его начала. С параметром `size=thumb` система SHALL отдавать уменьшенную копию (`size=full` или без параметра — исходное фото). Фото с заданным `id` никогда не меняется, поэтому ответ MUST разрешать браузеру хранить его в личном кеше бессрочно и MUST NOT разрешать общим кешам. Если мероприятия нет или фото ему не принадлежит — 404.

#### Scenario: Пользователь открывает фото
- **WHEN** незаписанный пользователь с заполненным профилем запрашивает фото мероприятия
- **THEN** система отвечает 200 с содержимым файла, типом картинки и заголовком `Cache-Control: private, max-age=31536000, immutable`

#### Scenario: Фото прошедшего мероприятия
- **WHEN** пользователь запрашивает фото мероприятия, которое уже прошло
- **THEN** система отвечает 200

#### Scenario: Фото другого мероприятия
- **WHEN** пользователь запрашивает `photo_id` мероприятия A по адресу мероприятия B
- **THEN** система отвечает 404

#### Scenario: Без токена
- **WHEN** клиент запрашивает фото без заголовка авторизации
- **THEN** система отвечает 401 и не отдаёт файл

#### Scenario: Уменьшенная копия
- **WHEN** организатор загрузил JPEG 4000×3000, а пользователь запрашивает его с `size=thumb`
- **THEN** система отвечает 200 с WebP шириной 800 px и высотой 600 px и тем же заголовком кеширования

#### Scenario: Маленькое фото не увеличивается
- **WHEN** пользователь запрашивает с `size=thumb` фото шириной 800 px или меньше
- **THEN** размер уменьшенной копии совпадает с размером исходного фото

#### Scenario: Фото, загруженное до появления копий
- **WHEN** фото было сохранено до этого изменения и пользователь запрашивает его с `size=thumb`
- **THEN** система отвечает 200 с уменьшенной копией

#### Scenario: Недопустимый размер
- **WHEN** пользователь запрашивает фото с `size=huge`
- **THEN** система отвечает 422

## ADDED Requirements

### Requirement: Картинка категории
Система SHALL по `GET /categories/{id}/covers/{cover_id}` отдавать картинку категории (`size=full` по умолчанию или `size=thumb` — уменьшенную копию шириной не больше 800 px) любому пользователю с заполненным профилем. Картинка с заданным `cover_id` не меняется: замена картинки даёт новый `cover_id` и новый адрес, поэтому ответ MUST разрешать личный кеш браузера бессрочно и MUST NOT разрешать общие кеши. Если категории нет или `cover_id` не её текущая картинка — 404; недопустимый `size` — 422.

#### Scenario: Картинка категории
- **WHEN** пользователь с заполненным профилем запрашивает картинку категории «Кино» по её `cover_id`
- **THEN** система отвечает 200 с картинкой, типом `image/webp` и заголовком `Cache-Control: private, max-age=31536000, immutable`

#### Scenario: Уменьшенная копия картинки категории
- **WHEN** пользователь запрашивает ту же картинку с `size=thumb`
- **THEN** система отвечает 200 с картинкой шириной не больше 800 px

#### Scenario: Несуществующая категория
- **WHEN** пользователь запрашивает картинку категории с `id`, которого нет в справочнике
- **THEN** система отвечает 404

#### Scenario: Картинка другой категории
- **WHEN** пользователь запрашивает `cover_id` категории «Спорт» по адресу категории «Кино»
- **THEN** система отвечает 404

#### Scenario: Без токена и с черновиком профиля
- **WHEN** клиент запрашивает картинку категории без токена, а затем пользователь с незаполненным профилем
- **THEN** система отвечает 401 и 403 с кодом `profile_incomplete` соответственно

### Requirement: Уменьшенные копии фото
При сохранении фото мероприятия система SHALL создавать уменьшенную копию в формате WebP: ширина не больше 800 px, пропорции исходного фото, без метаданных, меньшие фото не увеличиваются. Копия создаётся в той же транзакции, что и фото, и удаляется вместе с ним.

#### Scenario: Копия создаётся при загрузке
- **WHEN** организатор сохраняет набор с новым фото PNG 1600×900
- **THEN** у этого фото есть уменьшенная копия WebP 800×450

#### Scenario: Ошибка в одном из файлов
- **WHEN** сохранение набора отклонено из-за второго файла
- **THEN** ни фото, ни уменьшенные копии из этого запроса не сохраняются

### Requirement: Поиск по названию в каталоге
Система SHALL принимать в `GET /events` параметр `q`: возвращаются мероприятия, в названии которых есть эта подстрока без учёта регистра. Пробелы по краям обрезаются; пустая после обрезки строка равна отсутствию поиска; длиннее 100 символов — 422. Символы `%` и `_` ищутся как обычные символы. Поиск применяется вместе с `scope`, `period` и остальными фильтрами, `total` считается с его учётом.

#### Scenario: Подстрока без учёта регистра
- **WHEN** в каталоге есть «Турнир по «Мафии»» и «Вечер настольных игр», а пользователь вызывает `GET /events?q=маф`
- **THEN** в ответе только «Турнир по «Мафии»» и `total` = 1

#### Scenario: Поиск внутри вкладки
- **WHEN** пользователь организует «Йога в парке» и записан на «Йога утром», и вызывает `GET /events?scope=organized&q=йога`
- **THEN** в ответе только «Йога в парке»

#### Scenario: Пустой поиск
- **WHEN** пользователь вызывает `GET /events?q=%20%20`
- **THEN** ответ такой же, как без `q`

#### Scenario: Граница длины
- **WHEN** пользователь вызывает `GET /events` с `q` из 100 символов, а затем из 101
- **THEN** первый запрос успешен, второй отвечает 422

#### Scenario: Спецсимволы
- **WHEN** в каталоге есть «Скидка 50% на кино» и «Кино в парке», а пользователь вызывает `GET /events?q=50%25`
- **THEN** в ответе только «Скидка 50% на кино»

# Spec Delta

## ADDED Requirements

### Requirement: Фильтр по городу
Система SHALL принимать в `GET /events` параметр `city_id` (целое): возвращаются только мероприятия этого города. Фильтр применяется при любых `scope` и `period` вместе с остальными фильтрами, поиском и пагинацией; `total` считается с его учётом. Для несуществующего города система MUST отвечать 422 `city_not_found`; без параметра фильтр по городу не применяется.

#### Scenario: Мероприятия одного города
- **WHEN** есть мероприятия в Москве и Казани, и пользователь вызывает `GET /events?city_id=<id Казани>`
- **THEN** в ответе только мероприятия в Казани, `total` равен их числу

#### Scenario: Без параметра
- **WHEN** пользователь вызывает `GET /events` без `city_id`
- **THEN** в ответе мероприятия всех городов

#### Scenario: Вместе с другими фильтрами
- **WHEN** пользователь вызывает `GET /events?city_id=<id Казани>&category_id=3&min_free_places=1`
- **THEN** в ответе только мероприятия категории 3 в Казани, где есть свободные места

#### Scenario: Свои и прошедшие мероприятия
- **WHEN** пользователь записан на прошедшие мероприятия в Москве и Казани и вызывает `GET /events?scope=joined&period=past&city_id=<id Москвы>`
- **THEN** в ответе только прошедшее мероприятие в Москве

#### Scenario: Город без мероприятий
- **WHEN** пользователь вызывает `GET /events?city_id=<id города без мероприятий>`
- **THEN** система отвечает 200 с пустым `items` и `total` = 0

#### Scenario: Несуществующий город
- **WHEN** пользователь вызывает `GET /events?city_id=999999`
- **THEN** система отвечает 422 `city_not_found`

#### Scenario: Некорректное значение
- **WHEN** пользователь вызывает `GET /events?city_id=abc`
- **THEN** система отвечает 422

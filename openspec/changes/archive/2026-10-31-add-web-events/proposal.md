# Proposal

## Why

Backend мероприятий готов (`add-events`), но в веб-клиенте их нет: после входа пользователь видит только свой профиль. Эта порция делает мероприятия основой интерфейса — каталог как главная страница, просмотр, создание, запись и управление участниками — и добавляет в API фильтр «мои мероприятия», без которого нельзя показать, где пользователь участвует и что организует.

## What Changes

- **Backend**: `GET /events` получает параметры:
  - `scope` — `all` (по умолчанию, общий каталог), `joined` (записан, но не организатор), `organized` (автор);
  - `period` — `upcoming` (по умолчанию) или `past`; прошедшие сортируются от новых к старым; `scope=all` с `period=past` — 422;
  - `min_free_places` — не меньше N свободных мест (1–100);
  - в общем каталоге (`scope=all`) автоматически скрываются мероприятия, на которые пользователь не может записаться по возрасту.
- **Шапка** для авторизованного пользователя:
  - логотип и ссылка «Мероприятия» ведут на главную;
  - кнопка «Создать мероприятие» (на мобильном — иконка «+»);
  - колокольчик уведомлений — заглушка с текстом «Уведомлений пока нет»;
  - меню профиля под аватаром с инициалами: имя и телефон, «Профиль», «Выйти». **BREAKING** для UI: кнопка «Выйти» уходит из шапки в меню.
- **Главная `/`** — список мероприятий:
  - вкладки «Найти компанию», «Участвую», «Организую»; в двух последних переключатель «Предстоящие | Прошедшие»;
  - фильтры по категории, диапазону дат (один клик — один день) и минимальному числу свободных мест, «Показать ещё», состояние в адресе страницы;
  - карточки: категория, дата и время, название, место, возраст, свободные места, «Вы записаны»;
  - пустые состояния для каждой вкладки.
- **Страница `/events/:id`**: данные мероприятия, запись и отказ с причинами недоступности, для автора и администратора — редактирование на месте по стандарту «Окна и карточки с данными», удаление с подтверждением, список участников с исключением (с подтверждением); прошедшее мероприятие — только просмотр.
- **Создание мероприятия** в модальном окне по стандарту; после сохранения — переход на страницу нового мероприятия.
- После входа, онбординга и для корня сайта пользователь попадает на главную `/`, а не на `/profile`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `events`: требование «Каталог мероприятий» дополняется параметрами `scope`, `period` и `min_free_places`, а общий каталог — возрастным фильтром.
- `web-app`: меняются «Доступ к страницам», «Ввод кода», «Онбординг» (главная страница — `/`) и «Выход» (кнопка в меню профиля); добавляются требования к шапке, списку мероприятий, странице мероприятия, созданию, редактированию, записи и управлению участниками.

## Impact

- Backend: `app/routers/events.py`, `app/services/event_service.py`, тесты каталога. Схема БД и миграции не меняются.
- Frontend: новый слой `web/src/api/events.ts`, шапка в `App.vue` (компоненты меню и уведомлений), маршруты, страницы `EventsView` и `EventView`, компоненты карточки, формы и диалогов, утилиты форматирования даты и времени, тесты Vitest.
- Новых npm-зависимостей нет: используются компоненты PrimeVue 4 (`Menu`, `Popover`, `Tabs`, `SelectButton`, `Select`, `DatePicker`, `Dialog`, `ConfirmDialog`, `InputNumber`, `Textarea`).
- Документация: `README.md` (сценарий работы в интерфейсе), `docs/architecture.md` (структура `web/src`).

## Вне scope

- Реальные уведомления, их хранение и бейдж с количеством — только заглушка.
- Пункт «Уведомления» в меню профиля, раздел администрирования, переключатель темы.
- Поиск по тексту, сортировки кроме описанных, просмотр полных профилей участников.
- Отмена мероприятия со статусом, восстановление удалённого, черновики формы создания.
- Изменения правил backend, кроме фильтров `scope` и `period` (лимиты, права, возраст — без изменений).

# Spec Delta

## MODIFIED Requirements

### Requirement: Каталог мероприятий
Система SHALL по `GET /events` возвращать `items` и `total`. По умолчанию (`scope=all`, `period=upcoming`) — только предстоящие мероприятия (`starts_at` позже текущего момента) по возрастанию `starts_at`, при равенстве — по `id`. Фильтры: `category_id`, `from` (`starts_at` не раньше), `to` (`starts_at` раньше). Пагинация: `limit` 1–100, по умолчанию 20, `offset` от 0; недопустимые значения — 422. `total` — число с учётом фильтров, без пагинации.

#### Scenario: Только предстоящие
- **WHEN** в системе есть прошедшее мероприятие и два предстоящих
- **THEN** `GET /events` возвращает только два предстоящих, ближайшее первым, и `total` = 2

#### Scenario: Фильтр по категории
- **WHEN** пользователь вызывает `GET /events?category_id=<Спорт>`
- **THEN** в ответе только мероприятия категории «Спорт»

#### Scenario: Фильтр по диапазону дат
- **WHEN** пользователь вызывает `GET /events` с `from` = начало 1 декабря и `to` = начало 2 декабря
- **THEN** в ответе мероприятия, начинающиеся 1 декабря, а мероприятие, начинающееся ровно в начале 2 декабря, не попадает

#### Scenario: Пагинация
- **WHEN** есть 25 предстоящих мероприятий и пользователь вызывает `GET /events?limit=10&offset=20`
- **THEN** в ответе 5 мероприятий и `total` = 25

#### Scenario: Слишком большой лимит страницы
- **WHEN** пользователь вызывает `GET /events?limit=101`
- **THEN** система отвечает 422

## ADDED Requirements

### Requirement: Мои мероприятия в каталоге
Система SHALL принимать в `GET /events` параметр `scope`: `all` (по умолчанию) — все мероприятия; `joined` — мероприятия, на которые записан текущий пользователь и организатором которых он не является; `organized` — мероприятия, автором которых он является. Остальные значения — 422. Фильтры, сортировка и пагинация применяются к выбранному набору.

#### Scenario: Участвую
- **WHEN** пользователь организует мероприятие A, записан на мероприятие B и не записан на C, все предстоящие, и вызывает `GET /events?scope=joined`
- **THEN** в ответе только B и `total` = 1

#### Scenario: Организую
- **WHEN** тот же пользователь вызывает `GET /events?scope=organized`
- **THEN** в ответе только A

#### Scenario: После отказа
- **WHEN** пользователь отказался от участия в мероприятии и вызывает `GET /events?scope=joined`
- **THEN** этого мероприятия нет в ответе

#### Scenario: Фильтр категории внутри своих
- **WHEN** пользователь вызывает `GET /events?scope=organized&category_id=<Спорт>`
- **THEN** в ответе только его мероприятия категории «Спорт»

#### Scenario: Неизвестный scope
- **WHEN** пользователь вызывает `GET /events?scope=mine`
- **THEN** система отвечает 422

### Requirement: Прошедшие мероприятия в каталоге
Система SHALL принимать в `GET /events` параметр `period`: `upcoming` (по умолчанию) — `starts_at` позже текущего момента, по возрастанию `starts_at`; `past` — `starts_at` не позже текущего момента, по убыванию `starts_at`, при равенстве — по `id`. `period=past` допустим только со `scope=joined` или `scope=organized`; со `scope=all` и для неизвестных значений — 422.

#### Scenario: Прошедшие свои мероприятия
- **WHEN** пользователь организовал мероприятия, прошедшие вчера и неделю назад, и одно предстоящее, и вызывает `GET /events?scope=organized&period=past`
- **THEN** в ответе два прошедших, вчерашнее первым, и `total` = 2

#### Scenario: Мероприятие в момент начала
- **WHEN** `starts_at` мероприятия равен текущему моменту
- **THEN** оно попадает в `period=past` и не попадает в `period=upcoming`

#### Scenario: Прошедшие в общем каталоге
- **WHEN** пользователь вызывает `GET /events?period=past` без `scope` или со `scope=all`
- **THEN** система отвечает 422

#### Scenario: Неизвестный period
- **WHEN** пользователь вызывает `GET /events?scope=joined&period=today`
- **THEN** система отвечает 422

### Requirement: Возрастной фильтр каталога
В общем каталоге (`scope=all`) система SHALL не возвращать мероприятия, у которых `min_age` больше полных лет текущего пользователя на текущую дату — то есть те, на которые он не сможет записаться. Во вкладках `scope=joined` и `scope=organized` возрастной фильтр не применяется. `total` считается с учётом фильтра.

#### Scenario: Подросток в общем каталоге
- **WHEN** пользователю 14 лет, а в каталоге есть предстоящие мероприятия 0+, 14+, 16+ и 18+
- **THEN** `GET /events` возвращает только 0+ и 14+, `total` = 2

#### Scenario: Ограничению исполняется сегодня
- **WHEN** пользователю сегодня исполнилось 18 лет
- **THEN** мероприятия 18+ попадают в общий каталог

#### Scenario: Своё мероприятие выше возраста
- **WHEN** 17-летний организатор создал мероприятие 18+
- **THEN** оно есть в `scope=organized`, но не в общем каталоге

### Requirement: Фильтр по свободным местам
Система SHALL принимать в `GET /events` параметр `min_free_places` (целое 1–100): возвращаются только мероприятия, у которых `max_participants` минус число записанных не меньше заданного. Фильтр применяется при любых `scope` и `period`, `total` считается с его учётом. Значения вне диапазона — 422.

#### Scenario: Граница свободных мест
- **WHEN** у мероприятия лимит 5 и записано 3 человека, а пользователь вызывает `GET /events?min_free_places=2`
- **THEN** мероприятие есть в ответе, а при `min_free_places=3` — нет

#### Scenario: Заполненные мероприятия скрыты
- **WHEN** пользователь вызывает `GET /events?min_free_places=1`
- **THEN** в ответе нет мероприятий без свободных мест

#### Scenario: Недопустимое значение
- **WHEN** пользователь вызывает `GET /events?min_free_places=0` или `min_free_places=101`
- **THEN** система отвечает 422

## MODIFIED Requirements

### Requirement: Справочник категорий
Система SHALL хранить категории мероприятий в отдельном справочнике: `id` (целое число), `name` (уникальная строка), `icon` (имя иконки primeicons, например `pi-video`) и обязательную картинку категории. Категорию без картинки и без иконки MUST NOT быть возможно сохранить — это ограничение БД. Изначально справочник содержит «Настольные игры», «Прогулки», «Спорт», «Кино». Система SHALL по `GET /categories` возвращать все категории, упорядоченные по `id`, любому авторизованному пользователю, в том числе с незаполненным профилем; категория в ответах (справочник и поле `category` мероприятия) содержит `id`, `name`, `icon` и `cover_id`.

#### Scenario: Получение категорий
- **WHEN** пользователь с заполненным профилем вызывает `GET /categories`
- **THEN** система отвечает 200 со списком категорий, в котором есть «Настольные игры», «Прогулки», «Спорт» и «Кино», у каждой есть `id`, `name`, непустой `icon` и `cover_id`

#### Scenario: Черновик запрашивает категории
- **WHEN** пользователь с незаполненным профилем вызывает `GET /categories`
- **THEN** система отвечает 200 с тем же списком категорий

#### Scenario: Категория в мероприятии
- **WHEN** пользователь получает мероприятие категории «Кино»
- **THEN** поле `category` содержит `id`, `name` = «Кино», `icon` и `cover_id` той же категории, что и в `GET /categories`

#### Scenario: Категория без картинки
- **WHEN** в справочник пытаются добавить категорию без картинки или без иконки
- **THEN** БД отклоняет запись

### Requirement: Просмотр мероприятия
Система SHALL по `GET /events/{id}` возвращать мероприятие любому авторизованному пользователю, в том числе с незаполненным профилем, и в том числе уже начавшееся или прошедшее. Для несуществующего `id` система MUST отвечать 404.

#### Scenario: Просмотр чужого мероприятия
- **WHEN** пользователь, не записанный на мероприятие, вызывает `GET /events/{id}`
- **THEN** система отвечает 200 с мероприятием и `is_joined` = false

#### Scenario: Черновик открывает мероприятие
- **WHEN** пользователь с незаполненным профилем вызывает `GET /events/{id}`
- **THEN** система отвечает 200 с мероприятием, `is_joined` = false, `organizer.telegram` = `null`

#### Scenario: Прошедшее мероприятие
- **WHEN** пользователь запрашивает мероприятие, которое уже прошло
- **THEN** система отвечает 200

#### Scenario: Несуществующее мероприятие
- **WHEN** пользователь запрашивает мероприятие с несуществующим `id`
- **THEN** система отвечает 404

### Requirement: Возрастной фильтр каталога
В общем каталоге (`scope=all`) система SHALL не возвращать мероприятия, у которых `min_age` больше полных лет текущего пользователя на текущую дату — то есть те, на которые он не сможет записаться. Если дата рождения пользователя не задана, возрастной фильтр MUST NOT применяться. Во вкладках `scope=joined` и `scope=organized` возрастной фильтр не применяется. `total` считается с учётом фильтра.

#### Scenario: Подросток в общем каталоге
- **WHEN** пользователю 14 лет, а в каталоге есть предстоящие мероприятия 0+, 14+, 16+ и 18+
- **THEN** `GET /events` возвращает только 0+ и 14+, `total` = 2

#### Scenario: Ограничению исполняется сегодня
- **WHEN** пользователю сегодня исполнилось 18 лет
- **THEN** мероприятия 18+ попадают в общий каталог

#### Scenario: Своё мероприятие выше возраста
- **WHEN** 17-летний организатор создал мероприятие 18+
- **THEN** оно есть в `scope=organized`, но не в общем каталоге

#### Scenario: Дата рождения не задана
- **WHEN** пользователь с незаполненным профилем без даты рождения вызывает `GET /events`, а в каталоге есть предстоящие мероприятия 0+ и 18+
- **THEN** в ответе оба мероприятия, `total` = 2

### Requirement: Доступ к ручкам мероприятий
Все ручки категорий и мероприятий SHALL требовать действующий access-токен: без токена — 401. Ручки просмотра (`GET /categories`, картинки категорий, `GET /events`, `GET /events/{id}`, фото мероприятия) MUST быть доступны и пользователю с незаполненным профилем. Остальные ручки мероприятий (создание, изменение, удаление, изменение фото, запись, отказ, список и исключение участников) MUST отвечать пользователю с незаполненным профилем 403 с кодом `profile_incomplete`.

#### Scenario: Каталог без токена
- **WHEN** клиент вызывает `GET /events` без заголовка авторизации
- **THEN** система отвечает 401

#### Scenario: Черновик смотрит каталог
- **WHEN** пользователь с незаполненным профилем вызывает `GET /events`
- **THEN** система отвечает 200

#### Scenario: Черновик записывается
- **WHEN** пользователь с незаполненным профилем вызывает `POST /events/{id}/join`
- **THEN** система отвечает 403 с кодом `profile_incomplete`

#### Scenario: Черновик создаёт мероприятие
- **WHEN** пользователь с незаполненным профилем вызывает `POST /events` с корректными полями
- **THEN** система отвечает 403 с кодом `profile_incomplete`, мероприятие не создаётся

#### Scenario: Черновик запрашивает участников
- **WHEN** пользователь с незаполненным профилем вызывает `GET /events/{id}/participants`
- **THEN** система отвечает 403 с кодом `profile_incomplete`

### Requirement: Получение фото мероприятия
Система SHALL по `GET /events/{id}/photos/{photo_id}` отдавать содержимое фото с его типом (`image/jpeg`, `image/png` или `image/webp`) любому пользователю, которому доступен просмотр мероприятия, в том числе после его начала. С параметром `size=thumb` система SHALL отдавать уменьшенную копию (`size=full` или без параметра — исходное фото). Фото с заданным `id` никогда не меняется, поэтому ответ MUST разрешать браузеру хранить его в личном кеше бессрочно и MUST NOT разрешать общим кешам. Если мероприятия нет или фото ему не принадлежит — 404.

#### Scenario: Пользователь открывает фото
- **WHEN** незаписанный пользователь с заполненным профилем запрашивает фото мероприятия
- **THEN** система отвечает 200 с содержимым файла, типом картинки и заголовком `Cache-Control: private, max-age=31536000, immutable`

#### Scenario: Черновик открывает фото
- **WHEN** пользователь с незаполненным профилем запрашивает фото мероприятия
- **THEN** система отвечает 200 с содержимым файла

#### Scenario: Фото прошедшего мероприятия
- **WHEN** пользователь запрашивает фото мероприятия, которое уже прошло
- **THEN** система отвечает 200

#### Scenario: Фото другого мероприятия
- **WHEN** пользователь запрашивает `photo_id` мероприятия A по адресу мероприятия B
- **THEN** система отвечает 404

#### Scenario: Без токена
- **WHEN** клиент запрашивает фото без заголовка авторизации
- **THEN** система отвечает 401 и не отдаёт файл

#### Scenario: Уменьшенная копия
- **WHEN** организатор загрузил JPEG 4000×3000, а пользователь запрашивает его с `size=thumb`
- **THEN** система отвечает 200 с WebP шириной 800 px и высотой 600 px и тем же заголовком кеширования

#### Scenario: Маленькое фото не увеличивается
- **WHEN** пользователь запрашивает с `size=thumb` фото шириной 800 px или меньше
- **THEN** размер уменьшенной копии совпадает с размером исходного фото

#### Scenario: Фото, загруженное до появления копий
- **WHEN** фото было сохранено до этого изменения и пользователь запрашивает его с `size=thumb`
- **THEN** система отвечает 200 с уменьшенной копией

#### Scenario: Недопустимый размер
- **WHEN** пользователь запрашивает фото с `size=huge`
- **THEN** система отвечает 422

### Requirement: Картинка категории
Система SHALL по `GET /categories/{id}/covers/{cover_id}` отдавать картинку категории (`size=full` по умолчанию или `size=thumb` — уменьшенную копию шириной не больше 800 px) любому авторизованному пользователю, в том числе с незаполненным профилем. Картинка с заданным `cover_id` не меняется: замена картинки даёт новый `cover_id` и новый адрес, поэтому ответ MUST разрешать личный кеш браузера бессрочно и MUST NOT разрешать общие кеши. Если категории нет или `cover_id` не её текущая картинка — 404; недопустимый `size` — 422.

#### Scenario: Картинка категории
- **WHEN** пользователь с заполненным профилем запрашивает картинку категории «Кино» по её `cover_id`
- **THEN** система отвечает 200 с картинкой, типом `image/webp` и заголовком `Cache-Control: private, max-age=31536000, immutable`

#### Scenario: Уменьшенная копия картинки категории
- **WHEN** пользователь запрашивает ту же картинку с `size=thumb`
- **THEN** система отвечает 200 с картинкой шириной не больше 800 px

#### Scenario: Несуществующая категория
- **WHEN** пользователь запрашивает картинку категории с `id`, которого нет в справочнике
- **THEN** система отвечает 404

#### Scenario: Картинка другой категории
- **WHEN** пользователь запрашивает `cover_id` категории «Спорт» по адресу категории «Кино»
- **THEN** система отвечает 404

#### Scenario: Без токена и с черновиком профиля
- **WHEN** клиент запрашивает картинку категории без токена, а затем пользователь с незаполненным профилем
- **THEN** система отвечает 401 и 200 с картинкой соответственно

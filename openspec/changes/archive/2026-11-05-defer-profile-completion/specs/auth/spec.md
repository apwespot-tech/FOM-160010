## MODIFIED Requirements

### Requirement: Ограничение частоты запроса кода
Система SHALL принимать запрос нового кода для одного номера не чаще одного раза в 60 секунд. Интервал MUST отсчитываться от создания последнего кода этого номера, который ещё не был успешно проверен; успешно проверенный код повторному запросу не мешает. Более ранний запрос MUST отклоняться с кодом 429 и указанием, через сколько секунд можно повторить.

#### Scenario: Повторный запрос раньше 60 секунд
- **WHEN** код для номера запрошен 30 секунд назад, не был проверен, и клиент запрашивает код снова
- **THEN** система отвечает 429 с оставшимся временем ожидания и действующий код не меняется

#### Scenario: Повторный запрос ровно через 60 секунд
- **WHEN** с момента предыдущего запроса прошло 60 секунд
- **THEN** система создаёт новый код и отвечает 200

#### Scenario: Повторный вход сразу после выхода
- **WHEN** пользователь 20 секунд назад запросил код, успешно его проверил, вышел и запрашивает код снова
- **THEN** система создаёт новый код и отвечает 200, а тестовая ручка возвращает этот новый код

#### Scenario: Код отклонён по попыткам или сроку
- **WHEN** код запрошен 30 секунд назад и стал недействительным после пяти неверных попыток, а клиент запрашивает новый
- **THEN** система отвечает 429: интервал отсчитывается от непроверенного кода, даже если он уже недействителен

#### Scenario: Одновременные запросы после успешного входа
- **WHEN** после успешной проверки кода два запроса нового кода для того же номера приходят одновременно
- **THEN** ровно один создаёт код и получает 200, второй получает 429

### Requirement: Ограничение доступа при незаполненном профиле
Пока профиль пользователя не заполнен, система SHALL разрешать ему ручки просмотра: свой профиль (`GET`, `PATCH /profile`), категории и их картинки, города, каталог и просмотр мероприятия, фото мероприятий, картинки профилей. На остальные защищённые ручки — действия с мероприятиями и их фото, список и исключение участников, загрузку и удаление аватара и обложки, чужие профили — система MUST отвечать 403 с кодом ошибки `profile_incomplete`.

#### Scenario: Черновик обращается к чужому профилю
- **WHEN** пользователь с незаполненным профилем вызывает `GET /profile/{id}`
- **THEN** система отвечает 403 с кодом `profile_incomplete`

#### Scenario: Черновик смотрит каталог
- **WHEN** пользователь с незаполненным профилем вызывает `GET /events`, `GET /events/{id}`, `GET /categories` и `GET /cities`
- **THEN** система отвечает 200 на каждый запрос

#### Scenario: Черновик записывается или создаёт мероприятие
- **WHEN** пользователь с незаполненным профилем вызывает `POST /events/{id}/join` или `POST /events`
- **THEN** система отвечает 403 с кодом `profile_incomplete`, запись и мероприятие не создаются

#### Scenario: Черновик заполняет профиль
- **WHEN** пользователь с незаполненным профилем вызывает `PATCH /profile` с именем и датой рождения
- **THEN** запрос выполняется, и после этого ограничение снимается

#### Scenario: Заполнено только имя
- **WHEN** пользователь задал имя, но не дату рождения, и вызывает `POST /events/{id}/join`
- **THEN** система отвечает 403 с кодом `profile_incomplete`

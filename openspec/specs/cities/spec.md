# cities Specification

## Purpose

Справочник городов, общий для профилей пользователей и мероприятий: единые значения города для отображения и будущих фильтров.

## Requirements

### Requirement: Справочник городов
Система SHALL хранить города в справочнике: `id` (целое) и `name` (уникальная строка). Изначально справочник содержит крупные города России, в том числе «Москва» и «Санкт-Петербург»; пополняется только миграциями. Система SHALL по `GET /cities` возвращать все города, упорядоченные по названию, пользователю с заполненным профилем.

#### Scenario: Получение городов
- **WHEN** пользователь с заполненным профилем вызывает `GET /cities`
- **THEN** система отвечает 200 со списком городов по алфавиту, у каждого `id` и `name`, в списке есть «Москва» и «Санкт-Петербург»

#### Scenario: Уникальность названия
- **WHEN** в справочник пытаются добавить второй город «Москва»
- **THEN** БД отклоняет запись

#### Scenario: Доступ без токена и черновиком
- **WHEN** клиент вызывает `GET /cities` без токена, а затем пользователь с незаполненным профилем
- **THEN** система отвечает 401 и 403 с кодом `profile_incomplete` соответственно

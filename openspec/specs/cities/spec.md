# cities Specification

## Purpose

Справочник городов, общий для профилей пользователей и мероприятий: единые значения города для отображения и будущих фильтров.

## Requirements

### Requirement: Справочник городов
Система SHALL хранить города в справочнике: `id` (целое) и `name` (строка, уникальная без учёта регистра). Изначально справочник содержит крупные города России, в том числе «Москва» и «Санкт-Петербург»; его меняют миграции и администратор через API. Система SHALL по `GET /cities` возвращать все города, упорядоченные по названию, любому авторизованному пользователю, в том числе с незаполненным профилем.

#### Scenario: Получение городов
- **WHEN** пользователь с заполненным профилем вызывает `GET /cities`
- **THEN** система отвечает 200 со списком городов по алфавиту, у каждого `id` и `name`, в списке есть «Москва» и «Санкт-Петербург»

#### Scenario: Уникальность названия
- **WHEN** в справочник пытаются добавить второй город «Москва» или город «москва»
- **THEN** БД отклоняет запись

#### Scenario: Доступ без токена и черновиком
- **WHEN** клиент вызывает `GET /cities` без токена, а затем пользователь с незаполненным профилем
- **THEN** система отвечает 401 и 200 со списком городов соответственно

### Requirement: Права на изменение справочника городов
Ручки создания, переименования и удаления города SHALL быть доступны только администратору. Без токена система MUST отвечать 401, пользователю с незаполненным профилем — 403 `profile_incomplete`, остальным не-администраторам — 403 `forbidden`, при этом справочник не меняется.

#### Scenario: Обычный пользователь добавляет город
- **WHEN** пользователь без роли `admin` вызывает `POST /cities` с `name` = «Тверь»
- **THEN** система отвечает 403 и города нет в `GET /cities`

#### Scenario: Без токена
- **WHEN** клиент вызывает `DELETE /cities/{id}` без токена
- **THEN** система отвечает 401 и город остаётся

### Requirement: Создание и переименование города
Система SHALL по `POST /cities` с `name` создавать город и отвечать 201 с `id` и `name`, а по `PATCH /cities/{id}` с `name` — переименовывать город и отвечать 200. `name` — 1–60 символов после обрезки пробелов по краям; `null`, пустое значение и другие поля MUST отклоняться с 422. Для несуществующего `id` — 404. Мероприятия и профили с этим городом показывают новое название.

#### Scenario: Создание города
- **WHEN** администратор отправляет `POST /cities` с `name` = « Тверь »
- **THEN** система отвечает 201 с `name` = «Тверь», и город есть в `GET /cities` на своём месте по алфавиту

#### Scenario: Название на границе длины
- **WHEN** администратор создаёт город с названием из 60 символов, а затем из 61
- **THEN** первый создаётся, на второй система отвечает 422

#### Scenario: Переименование
- **WHEN** администратор переименовывает город мероприятия и профиля
- **THEN** система отвечает 200, а мероприятие и профиль возвращают новое `city.name`

#### Scenario: Несуществующий город
- **WHEN** администратор отправляет `PATCH /cities/999`
- **THEN** система отвечает 404

### Requirement: Уникальность названия города
Название города SHALL быть уникально без учёта регистра. Создание или переименование в занятое название MUST отклоняться с 409 `city_name_taken`; при одновременных попытках занять одно название успешна MUST быть ровно одна.

#### Scenario: Занятое название в другом регистре
- **WHEN** администратор создаёт город «москва», а «Москва» уже есть
- **THEN** система отвечает 409 `city_name_taken`

#### Scenario: Смена регистра своего названия
- **WHEN** администратор переименовывает «Тверь» в «ТВЕРЬ»
- **THEN** система отвечает 200 и название меняется

#### Scenario: Одновременное создание
- **WHEN** два запроса одновременно создают город «Тверь»
- **THEN** один получает 201, другой 409 `city_name_taken`, город «Тверь» один

### Requirement: Удаление города
Система SHALL по `DELETE /cities/{id}` удалять город, на который не ссылается ни одно мероприятие (в том числе прошедшее), и отвечать 204; в профилях пользователей с этим городом город очищается (`city` = `null`). Если мероприятия есть — 409 `city_in_use`, город не меняется. Для несуществующего `id` — 404.

#### Scenario: Удаление города из профилей
- **WHEN** у города нет мероприятий, а у пользователя он указан в профиле
- **THEN** система отвечает 204, города нет в `GET /cities`, у пользователя `city` = `null`

#### Scenario: Город с прошедшим мероприятием
- **WHEN** у города есть только одно уже прошедшее мероприятие
- **THEN** система отвечает 409 `city_in_use`

#### Scenario: Удаление одновременно с созданием мероприятия
- **WHEN** администратор удаляет неиспользуемый город, а другой пользователь одновременно создаёт в нём мероприятие
- **THEN** либо удаление получает 409 `city_in_use` и мероприятие создаётся, либо город удаляется и создание получает 422 `city_not_found`

#### Scenario: Удаление одновременно с выбором города в профиле
- **WHEN** администратор удаляет город, а пользователь одновременно указывает его в профиле
- **THEN** город удаляется, а у пользователя в итоге `city` = `null`: либо его запрос получает 422 `city_not_found`, либо сохраняется и город очищается удалением

# Нефункциональные требования

## Безопасность и авторизация

- Авторизация обязательна. Без входа доступны только страницы и эндпоинты регистрации и входа.
- Пароли хранятся только в виде хеша (argon2 или bcrypt); открытый пароль не логируется и не возвращается в ответах.
- Проверка прав выполняется на backend для каждого запроса; скрытие элементов в UI не считается защитой.
- Секреты (пароли БД, ключи подписи токенов) задаются через переменные окружения из `.env`.
  В репозитории хранится только `.env.example` без реальных значений.

## Целостность данных

- Операции с ограниченным ресурсом (например, места в активности) выполняются атомарно,
  в одной транзакции, так что параллельные запросы не могут превысить лимит.
- Ограничения целостности дублируются на уровне БД (внешние ключи, уникальность, проверки), а не только в коде.
- Схема БД меняется только миграциями Alembic.

## Время

- Даты и время хранятся в UTC (`timestamptz`).
- Клиент отображает время в часовом поясе пользователя.

## Запуск и эксплуатация

- Весь проект поднимается одной командой `docker compose up --build` на чистой машине с Docker.
- Миграции применяются при старте backend автоматически.
- Инструкция по запуску поддерживается в актуальном состоянии в `README.md`.

## API и ошибки

- API возвращает JSON и корректные HTTP-коды (400/401/403/404/409/422 для ошибок клиента).
- Сообщения об ошибках понятны пользователю и не раскрывают внутренние детали (стек, SQL).

## Качество

- Каждое требование из `openspec/specs/` покрыто хотя бы одним автотестом.
- Код проходит линтеры и проверку типов (см. [rules.md](rules.md)).

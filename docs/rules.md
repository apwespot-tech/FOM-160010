# Правила проекта

## Процесс

- Функциональность добавляется только через изменение OpenSpec:
  `/opsx:propose` → `/opsx:apply` → `/opsx:archive`.
- Бизнес-правила, которых нет в спеках или в текущем изменении, не реализуются «на всякий случай».
  Если требование неясно — сначала уточнить и записать его в спеку.
- После архивации изменения `openspec/specs/` должна соответствовать реализованному поведению.

## Git

- Работа ведётся по процессу курса: [git-workflow.md](git-workflow.md).
- Общую ветку `main` не изменять; каждая задача — отдельная рабочая ветка от личной `main`, сдача через PR.
- Сообщения коммитов в формате Conventional Commits: `feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`.
- В репозиторий не попадают `.env`, секреты, дампы БД, `node_modules/`, сборки.

## Backend (Python)

- Форматирование и линтинг — `ruff`, проверка типов — `mypy`.
- Слои: роутеры (HTTP) → сервисы (бизнес-логика) → репозитории/модели (SQLAlchemy). Бизнес-логика не пишется в роутерах.
- Входные и выходные данные описываются схемами Pydantic.
- Любое изменение схемы БД — новая миграция Alembic.
- Тесты — `pytest`, для поведения из спек обязательны.

## Frontend (Vue + TypeScript)

- TypeScript в режиме `strict`, Composition API с `<script setup lang="ts">`.
- Линтинг и форматирование — ESLint и Prettier.
- Обращения к API собраны в отдельном слое (`web/src/api/`), компоненты не вызывают `fetch` напрямую.
- Компоненты UI — PrimeVue 4 (MIT). Пакеты Prime с коммерческой лицензией (PrimeVue 5+, `@primeuix/themes` 3+, `primeicons` 8+) не подключать без отдельного решения.
- Тесты — Vitest и Vue Test Utils, для поведения из спек обязательны.

## UI

- **Адаптивность, mobile-first.** Базовые стили — для телефона, шире — через `min-width`. Брейкпоинты: мобильный до 639 px, планшет 640–1023 px, компьютер от 1024 px (`web/src/styles.css` и `web/src/utils/breakpoints.ts`, держать в синхроне). Каждую страницу проверять на 360, 768 и 1280 px: горизонтальной прокрутки быть не должно.
- **Сенсорный ввод.** Поля и кнопки не ниже 44 px. Шрифт в полях 16 px, чтобы iOS не масштабировала страницу. Для полей — правильные `type`, `inputmode` и `autocomplete`.
- **Тема.** По умолчанию светлая. Цвета — только через токены пресета (`web/src/theme.ts`) и переменные `--app-*` (`web/src/styles.css`), без захардкоженных значений в компонентах. Тёмная тема включается классом `.app-dark` (пока не реализована).
- **Палитра.** Фиолетовый — основной цвет: кнопки, ссылки, фокус. Оранжевый (`--app-accent`) — только акцент: бейджи, статусы, подсказки. Основные кнопки оранжевыми не делать.
- **Без градиентов и без эмодзи** — ни в интерфейсе, ни в текстах. Иконки — только `primeicons`.
- **Язык интерфейса — русский.** Ошибки сервера показываются понятными сообщениями по `detail.code`, у соответствующего поля.

### Окна и карточки с данными

Стандарт для модальных окон (PrimeVue `Dialog`) и карточек на странице, которые показывают данные сущности (профиль, активность и т. п.).

**Просмотр важнее редактирования.**
- Режим просмотра оформляется для чтения: плитки, иконки, акценты, крупный заголовок — то, что удобно смотреть. Под поля ввода его не подгоняют.
- По кнопке «Редактировать» содержимое окна или карточки может перестроиться в форму: подписи над полями, сетка как в окне создания той же сущности, без декоративных элементов просмотра. Форма открывается в том же окне (тот же адрес, крестик, футер), без перехода на другую страницу.
- Если данных немного и раскладка просмотра уже совпадает с формой (например, карточка профиля), можно менять значения на поля прямо на своих местах — так переключение спокойнее.
- Неизменяемые в редактировании данные (например, телефон в своём профиле) либо остаются текстом, либо скрываются, если форма перестраивается.
- Пустое необязательное значение в просмотре показывается как «не указано», а в редактировании — пустым полем с плейсхолдером.
- Кнопка «Редактировать» на своём месте заменяется парой «Сохранить» и «Отмена» (основная справа; на мобильной ширине — в одну строку по половине ширины). После сохранения или отмены окно возвращается в режим просмотра.
- Ошибки показываются под соответствующим полем. Общая ошибка — над кнопками действий.
- Отмена отбрасывает все несохранённые изменения без запросов к серверу.

**Модальные окна.**
- Компонент — `Dialog` из PrimeVue с `modal`. Заголовок обязателен, крестик закрытия в шапке.
- Закрытие: крестик, `Esc`, кнопка «Отмена» или «Закрыть». Клик по фону закрывает окно, только если в нём нет несохранённых изменений.
- Размеры: на мобильной ширине окно занимает весь экран, на планшете и компьютере выравнивается по центру, ширина до 480 px (до 640 px для окон с двумя колонками данных). Содержимое прокручивается внутри окна, страница под ним не прокручивается.
- Кнопки действий — в футере окна. Основная действует справа, «Отмена» слева от неё. На мобильной ширине кнопки во всю ширину, основная сверху. Это раскладка класса `app-actions app-actions--inline`.
- Фокус при открытии ставится на первое поле ввода или основную кнопку и возвращается на исходный элемент после закрытия (поведение `Dialog` по умолчанию, не отключать).
